# Security and privacy controls

The lead API accepts same-origin JSON POST only, caps the request body and each field, validates enums/contact details/source path, rejects honeypot submissions, and verifies Turnstile success, hostname and action before a prepared D1 insert. D1 uniqueness on `submission_key` blocks replayed inserts. Receipts are issued only after successful storage; raw errors and PII are never logged or returned. The client puts no PII into URLs or session storage (only the server receipt id). Responses are no-store, no-CORS, with explicit Functions security headers. Static page headers use `public/_headers`; review live HTTP responses after deployment.

Apply a Cloudflare WAF/rate-limit rule to `/api/leads` as permitted by the account plan, and monitor abuse and quotas. In-memory rate limiting cannot be relied on across isolates. Turnstile does not replace origin checks, input validation or database access controls. Do not enable SMS outreach without distinct legally reviewed express consent. Content is rendered using Astro's HTML escaping, not injected as HTML. Keep preview separate and noindexed, and never store D1 data or secrets in repository logs.
